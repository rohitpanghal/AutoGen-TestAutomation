# AI Test Recorder — MVP

Record a manual test pass in Chrome, mark logical steps as you go, and get back a
human-readable test case plus a Playwright TypeScript test — generated by Claude,
then run and self-healed until it passes.

## How it works

```
Chrome extension (recorder)
    -> deterministic DOM capture (click / input / select / navigate / mark_step)
    -> POST /api/generate            -> returns { id } immediately (202)
    -> background job (serial queue, one at a time):
         deterministic locator builder (scopes ambiguous selectors before the LLM sees them)
         -> Claude (single structured call: test case + Playwright code)
         -> written to backend/generated-tests/<slug>--<id>.spec.ts
         -> LangGraph self-heal loop: run test -> if failing, Claude diagnoses + patches -> rerun
              -> until passing, a suspected real app bug is flagged, or attempts run out
    -> progress streamed over SSE (GET /api/jobs/:id/events) to a standalone
       results tab (extension/pages/run.html) the popup opens
```

Design choices, and why:

- **Manual "Mark Step" button** instead of asking the AI to infer step boundaries
  from a flat action list — boundaries are ground truth, not a guess.
- **One combined LLM call** (test design + code generation) via a single tool-use
  schema, instead of two separate agents — fewer handoffs, lower latency/cost.
- **Generation and healing run as one background job.** `POST /api/generate`
  returns a job id right away; the popup opens `pages/run.html?id=<id>` in a tab,
  which subscribes to `GET /api/jobs/:id/events` (Server-Sent Events) and renders
  live progress — generation, each heal attempt, each diagnosis, and finally a
  diff of what healing changed. Closing and reopening the tab is safe: the backend
  buffers events and replays them on reconnect (`Last-Event-ID`).
- **A strictly serial job queue.** Only one job — one heal loop, one headed
  browser — runs at a time. A second `POST /api/generate` returns its own id
  immediately and its job waits in line (the results tab shows "Queued"). This is
  also what keeps two runs from tearing down each other's `healingBrowser`
  session.
- **File-based storage** (`backend/data/`, `backend/generated-tests/`) instead of
  Postgres for V1. Swap in a database once tests need to be listed/shared/queried.
- Selector priority enforced via the prompt: `data-testid` > role > label > text >
  CSS, XPath only as a last resort — but for elements the recorder flagged as
  ambiguous (duplicate ids, non-unique role+text), the backend computes the
  **already-scoped** Playwright locator expression itself
  (`services/locatorBuilder.ts`) rather than asking the LLM to reason about
  uniqueness in prose. Handing Claude a precomputed, correct locator string to
  copy verbatim turned out far more reliable than telling it "don't use a bare
  `#id` if it's ambiguous."
- **Generated specs assert, not just replay.** The prompt requires every claim
  in `testCase.expectedResults` / a step's `expectedResult` to be backed by a
  real `expect(...)` in the generated code — grounded in what the recording
  already proves (a navigation → `expect(page).toHaveURL(...)`, the first
  element interacted with after a navigation/step boundary →
  `expect(locator).toBeVisible()`, plus whatever a step's user-authored
  `description` explicitly asks to verify). The model stays conservative about
  *what* it claims; this only closes the gap where a justified claim was
  previously left as prose with no code behind it.
- **The recorder captures literal values.** Input/select values (passwords
  included) are recorded and used verbatim in the generated `fill()` calls. They
  are stored in `backend/data/` and never printed to the server log unless
  `DEBUG=1` **and** `DEBUG_UNSAFE_LOGS=1` (see [Logging](#logging)). Treat
  `backend/data/` as secret.

## Self-healing loop

Runs inside every `/api/generate` job (and on demand via `POST /api/heal/:id`).
A small [LangGraph](https://langchain-ai.github.io/langgraphjs/) state machine
(`backend/src/services/healingGraph.ts`):

```
run test ─┬─ passed ───────────────────────────────► done
          └─ failed ─┬─ attempts exhausted ─────────► done (needs manual review)
                     └─ Claude diagnoses + patches ─┬─ suspects a real app bug ─► done (needs manual review)
                                                     └─ otherwise ───────────────► run test (loop)
```

Default **8** run→fix→run cycles (`MAX_HEAL_ATTEMPTS`, env-configurable; also the
ceiling a per-request `maxHealAttempts` is clamped to).

When the job has the recording to replay (always, for a normal generate), the
fixer is the **live headed-browser agent** (`services/healingBrowser.ts` +
`fixTestWithBrowser`): it replays the recorded flow to the first broken step,
parks a real Chromium there, and gives Claude tools to probe the live DOM
(`try_locator`, `aria_snapshot`, `get_html`, `advance`, `screenshot`) — a
proposed locator fix is rejected unless it resolves to exactly one element on the
real page. With no recording (a bare `deps` override in tests) it falls back to a
text-only single call.

Two safety properties matter more than the loop itself:

- **The fixer is told not to weaken assertions to make a test pass.** If the
  Playwright failure looks like the app genuinely behaves differently now (not a
  stale selector or a missing wait), the model sets `likelyRealBug: true`, leaves
  the code untouched, and the loop stops immediately. Surfaced to you as the
  `suspectedRealBug` flag / a callout on the results page.
- **Every fix lands in the same file.** `updateGeneratedTest` overwrites
  `generated-tests/<slug>--<id>.spec.ts` in place, so `git diff` shows exactly
  what the loop changed.

Caveat: unlike the selector-uniqueness fix, "don't weaken assertions" is a prompt
instruction only, not a deterministic check. Treat a `passed` result as "worth a
diff review before you trust it" — the results page shows that diff.

## API

| Method & path | Purpose |
|---|---|
| `POST /api/generate` | Body `{ testName, actions[], maxHealAttempts? }`. Enqueues a job; returns `202 { id }`. |
| `POST /api/heal/:id` | Re-run the self-heal loop for an existing generated test. Returns `202 { id }` (a new job id). |
| `GET /api/jobs/:id` | JSON snapshot: status + every progress event so far + final result. |
| `GET /api/jobs/:id/events` | Server-Sent Events stream of progress. |
| `DELETE /api/jobs/:id` | Request cancellation (aborts the in-flight Playwright run and LLM call). |
| `GET /api/recordings/:id` | The raw recorded actions for a job. |
| `GET /health` | `{ ok: true }`. |

## Setup

### 1. Backend

```
cd backend
npm install
cp .env.example .env   # then set ANTHROPIC_API_KEY
npm run dev
```

Runs on `http://localhost:4000`.

### 2. Extension

```
cd extension
npm install
npm run build
```

Then in Chrome: `chrome://extensions` → enable Developer mode → **Load unpacked**
→ select the `extension/` folder.

### 3. Record a test

1. Open the target app, click the extension icon, name the test, hit **Start Recording**.
2. Interact with the page normally (click, type, select, navigate).
3. Hit **Mark Step** whenever you've completed a logical step (e.g. "Login", "Open order").
4. Hit **Stop & Generate**. The popup fires `POST /api/generate` and opens a
   **results tab**. Generation + self-healing run there with live progress; when
   it finishes you get the test case, the (possibly healed) Playwright code, a
   diff of what healing changed, and every diagnosis. The spec is written to
   `backend/generated-tests/<slug>--<id>.spec.ts`.

Set `TEST_BASE_URL` in `backend/.env` to your app's URL first (used as
Playwright's `baseURL` for the heal runs and for `npm run test:generated`).

### 4. Run the generated test yourself

```
cd backend
npx playwright install   # first time only
npm run test:generated
```

### 5. Re-heal later (optional)

`POST /api/heal/:id` with the id from generation re-runs the loop against the
current spec on disk and streams to a results tab the same way. `HEAL_HEADED=1`
also runs the authoritative verification headed.

## Logging

Short one-line progress logs (`[generate] (id) …`, `[heal] …`) always print.
The verbose "dump the whole prompt / payload" blocks only print when `DEBUG=1`,
and even then recorded input values, emails, and long tokens are redacted —
unless `DEBUG_UNSAFE_LOGS=1`, which is local-debugging-only.

## Environment

```
ANTHROPIC_API_KEY=            # required
PORT=4000
TEST_BASE_URL=http://localhost:3000   # Playwright baseURL
MAX_HEAL_ATTEMPTS=8           # default + per-request clamp ceiling
HEAL_HEADED=0                # 1 => authoritative verification run is also headed
DEBUG=0                      # 1 => verbose payload/prompt tracing (redacted)
DEBUG_UNSAFE_LOGS=0          # 1 => don't redact values in those traces
```

## Project layout

```
extension/            Manifest V3 Chrome extension (TypeScript, no bundler)
  manifest.json
  src/
    content.ts         DOM event capture -> RecordedAction
    background.ts       recording state, navigation capture
    popup.ts             UI: start/stop/mark-step, then open the results tab
    run.ts               results tab: SSE progress, code, heal timeline, diff
    types.d.ts           shared ambient types
  popup/popup.html, popup.css
  pages/run.html, run.css

backend/              Node.js + Fastify + Anthropic SDK + LangGraph
  src/
    index.ts
    cors.ts                   shared origin allow-list
    routes/generate.ts        POST /api/generate
    routes/heal.ts            POST /api/heal/:id
    routes/jobs.ts            GET /api/jobs/:id[/events], DELETE /api/jobs/:id
    routes/recordings.ts     GET /api/recordings/:id
    services/anthropic.ts     structured tool-use calls to Claude (generate + fix)
    services/locatorBuilder.ts  deterministic ambiguity-safe Playwright locators
    services/testRunner.ts      runs one spec file with Playwright, captures output
    services/healingGraph.ts    LangGraph run/fix/retry loop
    services/healingBrowser.ts  long-lived headed Chromium the fix agent drives
    services/jobs.ts            in-process serial job queue + progress events
    services/storage.ts         file-based persistence
    services/logging.ts         DEBUG-gated, redacting log helpers
  generated-tests/    Playwright output + config
  data/               raw recordings + generation results (gitignored)
```
